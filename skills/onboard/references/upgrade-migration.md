# Upgrade Migration (v0.5.0)

Called by `/dominion:onboard --upgrade` when an existing `.dominion/` has schema_version < 0.5.0 (or absent).

## Pre-checks

1. Read `.dominion/config.toml` → extract `schema_version` (absent = "pre-0.5.0")
2. If `schema_version` == "0.5.0": "Already up to date at v0.5.0. No migration needed." → EXIT
3. If `schema_version` > "0.5.0": "Config is from v{schema_version}, plugin is v0.5.0. Update the plugin first." → EXIT

## Dry Run

Show what will change and ask for confirmation:

```
Upgrading {detected_version} → v0.5.0:
  + Add schema_version tracking to config.toml
  + Add [auto] fields: auto_continue (false), agent_timeout_minutes (15)
  + Add [pipeline] section for custom step sequences
  + Create .dominion/objectives.toml for multi-session tracking
  + Deploy wave-review.md heuristic
  + Regenerate hooks with pipeline continuity support

  Preserved: knowledge/, decisions, state.toml, phases/, agent customizations
```

Ask user to confirm (C-Thread). If declined: EXIT.

## Backup

```bash
mkdir -p .dominion/backup
cp .dominion/config.toml .dominion/backup/config.toml.pre-0.5.0
cp -r .claude/hooks/ .dominion/backup/hooks.pre-0.5.0/ 2>/dev/null || true
```

## Step 1: Migrate config.toml

Read current config.toml. Apply additive changes (NEVER remove existing values):

1. Add `schema_version = "0.5.0"` at top level (before `[project]`)
2. If `[auto]` section exists:
   - Add `auto_continue = false` if missing
   - Add `agent_timeout_minutes = 15` if missing
   - PRESERVE existing `max_retries` and `halt_on_severity`
3. If `[auto]` section doesn't exist:
   - Add full section: `[auto]\nmax_retries = 3\nhalt_on_severity = "critical"\nauto_continue = false\nagent_timeout_minutes = 15`
4. Add empty `[pipeline]` section with comment: `# Optional: override default step sequences`

Write config.toml. Validate: `python3 -c "import tomllib; tomllib.load(open('.dominion/config.toml','rb'))"`

## Step 2: Create objectives.toml

If `.dominion/objectives.toml` doesn't exist:
```toml
# Dominion objectives — multi-session feature tracking
```

## Step 3: Deploy new heuristics

If `.dominion/heuristics/wave-review.md` doesn't exist:
- Read `skills/onboard/data/heuristics/wave-review.md` (plugin source)
- Write to `.dominion/heuristics/wave-review.md`

Do NOT touch existing heuristics — they may have been customized.

## Step 4: Regenerate hooks

For each hook file in `.claude/hooks/`:
- Check for `# Generated by Dominion` marker in first 2 lines
- If marker present OR file doesn't exist: overwrite with v0.5.0 template from hooks-generation.md
- If marker absent (user-created): WARN: "Skipping {filename} — appears user-modified. See .dominion/backup/ for v0.5.0 template."

Key change: `session-start.sh` gains pipeline continuity directive (reads `auto_continue` from config, emits PIPELINE READY when conditions met).

Make hooks executable: `chmod +x .claude/hooks/*.sh`

## Step 5: Verify

1. `python3 -c "import tomllib; tomllib.load(open('.dominion/config.toml','rb'))"` — TOML valid
2. Read config.toml → confirm `schema_version = "0.5.0"`
3. Verify `.dominion/objectives.toml` exists
4. Verify `.dominion/heuristics/wave-review.md` exists
5. Count preserved items:
   - Knowledge entries: count from `knowledge/index.toml`
   - Decisions: count from `state.toml [[decisions]]`
   - Completed phases: count from `state.toml [[phases]]` where status == "complete"

## Step 6: Report

```
Migration complete: {detected_version} → v0.5.0

Preserved: {N} knowledge entries, {M} decisions, {P} completed phases

Next steps:
  1. Reinstall MCP server: uv tool install {mcp_install_path}
  2. Restart Claude Code session to activate new MCP tools
  3. New features: /dominion:status shows event feed and objectives
```

If active pipeline detected (state.toml position.status == "active"):
```
Active pipeline detected (Phase {phase}, step: {step}).
New features will activate for subsequent steps.
After restart: /dominion:orchestrate --resume to continue.
```

## Migration Registry

Future versions add steps here. Each migration is idempotent (safe to run multiple times).

```
v0.5.0:
  1. schema_version = "0.5.0"
  2. [auto].auto_continue, [auto].agent_timeout_minutes
  3. [pipeline] section
  4. objectives.toml
  5. wave-review.md heuristic
  6. Enhanced session-start.sh hook
```
